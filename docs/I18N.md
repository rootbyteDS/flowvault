# Sprachen (i18n)

FlowVault gibt es auf Deutsch und Englisch. Weitere Sprachen lassen sich ergänzen, ohne Code zu ändern, der die Oberfläche oder den Server betrifft: Eine Sprache ist ein Ordner mit Textdateien.

## Wie die Sprache gewählt wird

| Wo | Welche Sprache |
|----|----------------|
| Oberfläche | Wahl im Sprachwähler (Anmeldeseite und **Einstellungen → Sprache**, gespeichert nur in diesem Browser) → sonst die Browsersprache → sonst `DEFAULT_LANGUAGE` des Servers → sonst Deutsch |
| Fehlermeldungen der API | die Sprache der Oberfläche (der Browser sendet sie als `Accept-Language`) |
| Server-Logs, z. B. der Einrichtungscode | `DEFAULT_LANGUAGE` (`de` oder `en`, Standard `de`) |
| KI-Änderungstexte | Einstellung **Sprache der Texte** unter *Einstellungen → KI-Änderungstexte*, Standard `DEFAULT_LANGUAGE`. Die Texte entstehen einmal und werden gespeichert: Ein späterer Wechsel betrifft nur neue Texte |
| Fehlertexte aus Hintergrundläufen (Sync, Fehlerquote) | werden als Schlüssel gespeichert und beim Anzeigen übersetzt – sie folgen also der Sprache der Oberfläche, auch rückwirkend |

## Aufbau

```
shared/i18n/
  index.ts          Übersetzer, Sprachwahl, Meldungen für die Datenbank (ohne Abhängigkeiten)
  server.ts         Sprache auf dem Server (DEFAULT_LANGUAGE, Accept-Language), HttpError
  types.ts          Typen: Messages, MessageKey, PluralForms
  i18n.test.ts      Prüft, dass alle Sprachen vollständig und konsistent sind
  locales/
    index.ts        Registry aller Sprachen
    de/             Deutsche Texte – die Vorlage
    en/             Englische Texte
web/src/i18n.tsx    React-Anbindung: t(), rich(), paragraphs(), Sprachwähler-Logik
```

Server und Oberfläche teilen sich dieselben Texte. Die deutschen Dateien unter `locales/de/` bestimmen per TypeScript, welche Schlüssel jede Sprache liefern muss; `npm run typecheck` meldet fehlende oder überzählige Schlüssel, `npm test` zusätzlich abweichende Platzhalter und fehlende Pluralformen.

## Eine Sprache hinzufügen

Beispiel Französisch (`fr`):

1. Den Ordner `shared/i18n/locales/en/` nach `shared/i18n/locales/fr/` kopieren.
2. In jeder Datei die Werte übersetzen (die Schlüssel bleiben gleich). In `core.ts` den Namen der Sprache in ihr selbst und den Intl-Tag setzen:
   ```ts
   export const meta: Messages['meta'] = { name: 'Français', intl: 'fr-FR' };
   ```
3. In `fr/index.ts` stehen die Imports der Dateien – dort nichts ändern außer dem Namen der Konstante (`export const fr`).
4. In `shared/i18n/locales/index.ts` die Sprache eintragen:
   ```ts
   import { fr } from './fr/index.ts';
   export const catalogs = { de, en, fr } satisfies Record<string, Messages>;
   ```
5. `npm run typecheck && npm test` ausführen. Danach erscheint die Sprache im Sprachwähler, in `DEFAULT_LANGUAGE` und in der Auswahl der KI-Textsprache.

Nichts weiter nötig: Datum, Zahlen und relative Zeitangaben nutzt `Intl` mit dem Tag aus `meta.intl`, und die KI bekommt den Sprachnamen automatisch (`Intl.DisplayNames`).

## Texte schreiben

- **Schlüssel** sind verschachtelt nach Bereich: `t('workflow.addNote')`. Neue Texte zuerst in `de/` anlegen, dann in allen anderen Sprachen.
- **Platzhalter**: `{name}` wird durch `t('key', { name })` ersetzt.
- **Plural**: Ein Objekt statt eines Textes, `count` wählt die Form nach den Regeln der Sprache. `other` ist Pflicht; welche weiteren Formen (`zero`, `one`, `two`, `few`, `many`) eine Sprache braucht, bestimmt ihr Unicode-CLDR-Eintrag.
  ```ts
  count: { one: '{count} Workflow', other: '{count} Workflows' }
  ```
  Ein Schlüssel namens `other` darf deshalb nie ein normaler Text sein.
- **Formatierung im Text**: `<b>…</b>`, `<code>…</code> ` und eigene Tags. In der Oberfläche `rich('key', { tag: (text) => <… /> })` verwenden; für Erklärtexte in `InfoTip` genügt `paragraphs('key')` (Absätze durch eine Leerzeile trennen).
- **Lange Sätze nicht zerstückeln**: Lieber zwei vollständige Sätze mit eigenem Schlüssel als einen Satz aus Bruchstücken – andere Sprachen ordnen Wörter anders.
- **Verweise auf Beschriftungen** („Als Kopie anlegen“, „Vorschläge“) müssen zum Text der jeweiligen Sprache passen.

### Im Code

```tsx
import { t, rich, paragraphs, message } from './i18n.tsx';   // Oberfläche
import { HttpError, fail, requestT, t } from '../shared/i18n/server.ts';   // Server

t('dashboard.stats.workflows')
<InfoTip>{paragraphs('settings.health.alertsTip')}</InfoTip>
throw new HttpError(404, 'errors.workflow.notFound');
```

`t` liest die aktive Sprache aus einer Variablen. Ein Sprachwechsel baut die Oberfläche deshalb komplett neu auf (siehe `I18nProvider`). Ergebnisse von `t()` dürfen darum nicht beim Laden des Moduls in Konstanten gespeichert werden – Beschriftungen als Schlüssel ablegen und beim Rendern übersetzen.

### Texte, die in der Datenbank landen

Fertige Sätze würden die Sprache zum Zeitpunkt des Speicherns einfrieren. Stattdessen speichert der Server `i18n:{"k":"errors.n8n.unreachable","p":{"reason":"ECONNREFUSED"}}` (`packMessage`, `packError`). Die Oberfläche übersetzt mit `message(text)`; Text ohne dieses Präfix – etwa Meldungen von n8n selbst oder Einträge älterer Versionen – bleibt unverändert.
